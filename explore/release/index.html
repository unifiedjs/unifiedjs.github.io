    • #629 8241610 Thanks @paoValle! - fix: mute the code block rules under their @stylistic names too

      eol-last and padded-blocks were deprecated in ESLint v8.53.0 in favour of @stylistic/eslint-plugin, which carries them with its own prefix. The code blocks config switches both off, and now also switches off @stylistic/eol-last and @stylistic/padded-blocks, so the examples stay muted for users who run the plugin.

      Closes #601.

  49. mdx-js/eslint-mdx@eslint-mdx@3.9.0·1 month ago

    Minor Changes

    • #622 2c41867 Thanks @JounQin! - feat: add ESTree nodes for Markdown content

      Add MDCode, MDHeading, MDParagraph, MDText, MDList, MDListItem, MDBlockquote, MDEmphasis, MDStrong, MDInlineCode, MDLink, MDImage, MDBreak, MDThematicBreak, MDDefinition, MDDelete, MDFootnoteDefinition, MDFootnoteReference, MDImageReference, MDInlineMath, MDLinkReference, MDMath, MDTable, MDTableCell, MDTableRow, MDToml and MDYaml nodes with visitor keys. Restore whitespace JSXText tokens inside JSX elements so the AST body and tokens stay aligned.

      MDXCode and MDXHeading have been replaced by MDCode and MDHeading, including their emitted type strings.

      Closes #503.

      @types/estree@^1.0.10 is declared as an optional peer dependency.

    • #621 43af536 Thanks @JounQin! - feat: add MDXFlowExpression and MDXTextExpression nodes

      MDX content expressions are no longer emitted as top-level ExpressionStatement nodes, so no-unused-expressions no longer reports them. The new nodes expose their expression and are traversed via the extended visitor keys.

      Closes #581.

    • #637 fd72b28 Thanks @JounQin! - feat: use micromark token types directly

      Generate markdown and MDX structural tokens from the same micromark parse used for the mdast tree, map MDX JSX/expression events to ESLint token types, and merge them with acorn's JavaScript tokens. Markdown token types now use the original micromark labels; JSX text keeps using JSXText for compatibility.

    Patch Changes

    • #643 4241ceb Thanks @JounQin! - chore: include context in JSX parsing assertion messages

    • #632 5e0b172 Thanks @JounQin! - fix: emit empty MDX expressions

      Top-level and nested comment-only or empty expressions ({/* ... */}, {}) were skipped because their ESTree body is empty, leaving their brace tokens or parent children without a corresponding node. Emit an MDXFlowExpression or MDXTextExpression containing a JSXEmptyExpression instead.

    • #630 d41d8ee Thanks @JounQin! - fix: wrap MDX expressions in JSXExpressionContainer

      Flow expressions inside JSX children were emitted as raw expressions and used the parent element range. They are now wrapped in JSXExpressionContainer nodes with their own range; both flow and text expression containers now use the expression's own range.

      Closes #628.

    • #636 1c675f4 Thanks @JounQin! - fix: preserve markdown children of JSX elements

      Markdown nodes such as links and emphasis were dropped when they appeared inside JSX elements, making them look empty to rules like react/self-closing-comp.

    • #631 b476a1c Thanks @hippi345! - chore: migrate to devlop

      Replace node:assert with devlop so development-only assertions are stripped in production builds.

      Closes #568.

    • #639 b3eb3bf Thanks @JounQin! - fix: treat props as defined in MDX content, but not in mdxjsEsm
